# 外部人体模型

这个目录里已经放好了可用的资源，页面左侧「模型来源」选「外部模型」即可切换：

```
assets/
├── body.glb            人体网格（13380 顶点 / 26756 三角面，带 10 个形变目标），约 906 KB
└── body-regions.json   部位分区表（39 个区，含手指、脚趾、肘腕膝踝），约 50 KB
```

素材来自 **MakeHuman** 的基础网格、骨骼权重和宏目标（CC0 1.0，可自由使用与再分发），
由 `tools/make-body-glb.js` 转换而来。想重新生成或换个模型：

```
node tools/make-body-glb.js            # 首次会从 GitHub 下载约 3 MB 素材并缓存到 tools/.mh-cache
node tools/make-body-glb.js --no-regions   # 只导网格
```

脚本不依赖任何 npm 包，缓存存在时完全离线。生成时做了三件页面依赖的事：左右居中、脚踩到 y=0、
按腰部横截面找中轴 z；另外把形变目标里的**整体身高变化抽掉**了（MakeHuman 的男女宏目标顺带差了
14 cm 身高，不抽掉就会和身高滑块打架）。

> **必须用本地服务器打开**：`file://` 下浏览器不允许读取 `.glb` 和 `.json`，切换时会提示读不到资源。
> 在 `html-tools` 目录下随便起一个静态服务器即可，例如 `python -m http.server 8080`，
> 然后访问 `http://localhost:8080/3D人体标注/`。
>
> 部署到静态托管（EdgeOne Pages、Netlify、Vercel 这类）时注意：文件缺失时它们往往不返回 404，
> 而是拿首页 HTML 顶替，于是加载器会报「返回的不是 GLB」。这种情况就是 `body.glb` 没上传上去，
> 检查一下构建产物里有没有这个文件（有些平台默认不发布未被引用的二进制文件）。

已知差别：外部模型没有单独的五官区（MakeHuman 的骨骼里没有耳朵、眼睛），点到耳垂会说成「头部」附近；
程序化模型有 `eye` / `ear` 区，能直接说「左耳垂」。想要五官就得自己在分区表里加对应的区。

外生殖器两边都没有（MakeHuman 的基础网格也不带），由 `BodyModel.maleGenitals()` /
`BodyModel.femaleVulva()` 现搭一份补上，两个模型源共用，只在「显示私密部位」打开时可见可点：

- 男性四件：阴茎 / 阴茎头(龟头) / 左侧阴囊 / 右侧阴囊。阴茎往前偏下约 22° 出去，不是自然下垂——
  垂下来会压在阴囊上，两件叠在一起谁也标不准；抬到 22° 之后阴囊表面离阴茎轴还有 3cm，扣掉阴茎自己的
  半径净剩 1cm 以上的空隙，四件从「前下 45°」看过去互不遮挡。尺寸是按「好标记」定的，不是按解剖平均值：
  身高 170 上长约 8.2cm（含龟头）、粗 3.4cm，细长条在屏幕上只有几个像素宽，圈不住也点不准。
  阴囊分两瓣，球心距比半径小，交界处自然凹出约 0.7cm 的中缝（阴囊中隔），左右能分开标。
- 女性四件：左侧大阴唇 / 右侧大阴唇 / 阴道口(外阴前庭) / 阴蒂。网格没法真挖洞，「口子」是靠两道
  隆起的皱褶夹一片压低的深色板做出来的（深色件带 `shade: 'dark'`，调用方据此换 `MAT.privDark`）：
  - 两瓣不是椭球，是**纺锤**——`tube` 配 `profile(t)=sin(πt)^0.55` 让两头收成尖，再在局部坐标里
    横向压扁、朝外压薄（`scale(0.55, 1, 0.52)`，局部 x 是左右、y 是轴向、z 朝体外）。收尖之后合起来
    是杏仁形，长宽比 3 以上（170 身高上约 5.4cm 长、1.6cm 宽）；不收尖就是两颗蛋贴在胯上。
  - 两瓣朝外**只露 0.6cm 上下**（唇脊 = 实测体表 + 0.0038·身高，实测 0.55～0.7，外部模型会阴那头
    到 1.0）。露太多就是两根香肠贴在胯上，所以下半截是故意埋进肉里的。
  - 高度不是「在两锚点的弦上抬固定一截」，而是**顺着 out 打射线量出来的**（`femaleVulva` 里的
    `bulge()`，调用方给 `anchor.hit(origin, dir)` 回调，两个模型源各打自己那套体表）：弦是内接的，
    胯下体表在两锚点中间会拱到弦外面 0.3cm 以上，越高越瘦拱得越多。件薄到 0.6cm 之后这点差别
    就是「浮在体外」和「整件埋进肉里」的分界，按固定值抬必有一边翻车。
  - 中间那片深色板要**做满宽度**（横向 0.95，几乎和两瓣的中心线一样宽），不能只填缝的宽度：两瓣往
    两头收尖的地方缝会张开，板窄了那里就露出一条皮肤色，看着像缝断在中间。
  - 板的高度在「够深」和「露得出来」之间夹一下（`clamp(唇脊-0.0026H, 中线体表+0.0010H, 唇脊-0.0014H)`），
    量出来缝底比唇峰低 0.23～0.46cm：件薄了缝就深不到哪去，主要靠颜色认，深度只是帮衬。
  - 大阴唇是 `kind: 'limb'`（不是 `blob`），所以描述会说「左侧大阴唇 内侧(靠中线)，前端(靠阴蒂)」
    这种带轴向位置的话；前庭和阴蒂是 `face`，只报名字。
  - 这几件（和全身所有 `tube` / `blob` 出来的件）**接缝是焊过的**：three 的
    `LatheGeometry` / `SphereGeometry` 收尾那一圈拿 phi=2π 算，和 phi=0 那圈差 1e-16，接缝上
    留着一道无限薄的裂口，正好躺在这个平面里的射线会穿过去、一次都不命中。lathe 的接缝就在
    局部 +z（也就是 `ref`、这里的朝外方向），而量薄厚打的射线偏偏最爱走这个方向——件薄到
    0.6cm 之后表现出来就是「整件埋进了肉里」。`tube()` / `blob()` 现在把最后一圈的坐标抄成
    第一圈的，法线本来就一样，观感不变。球体两极的扇心还是个针孔（严格沿极轴打的射线会漏），
    这个是 three 的球体自带的，浏览器里点选碰不上，无头量东西时别沿件的极轴打就行。

锚点都在**正中面**上：男性一个点（裆部那一层的身体前表面 z，外部模型靠扫顶点量 `midFront()`，
不能拿内衣那套凸壳支撑距离顶替，那个量到的是大腿前侧，比正中面远三四厘米，整件会飘在体外）；
女性要两个点（裆高 ±0.012·身高 两处的前表面 z），两点连成的弦就是外阴所在那片体表，斜度由模型
自己定——程序化模型胯下几乎朝前，外部模型明显朝下偏后，写死一个斜度必有一边埋进肉里。这两个点
两边都是**打射线**量的（`body-model.js` 打躯干，`mesh-model.js` 打形变后的网格，趁它还没进
`group`、matrixWorld 还是单位矩阵时量）：胯下顶点稀，按顶点扫窄带常常扫不到，扫到的还可能是会阴
或大腿内侧，量出来能差好几厘米。换模型时如果 GLB 自带了这部分，把 `mesh-model.js` 里
`addPriv` 那两段按性别的补件删掉即可。

下面是格式说明，换自己的模型时按这个来。

## body.glb 的要求

| 项目 | 要求 |
| --- | --- |
| 格式 | glTF 二进制（`.glb`），单个网格；有多个网格时只取第一个 |
| 朝向 | 面朝 +Z，头顶朝 +Y，模型自己的左手在 +X 一侧 |
| 单位 | 米或厘米都行，整体高度小于 3 就按米处理（自动 ×100） |
| 位置 | 不用对齐，加载时会自动左右居中、把脚踩到 y=0、按腰部横截面找中轴 |
| 姿势 | A 型或 T 型都可以；自动分区两种都认 |
| 面数 | 建议 2 万～8 万三角面。太少了圈选点位会发飘，太多了低端机旋转会卡 |
| 贴图 | 不需要，工具只用自己的皮肤材质；带了也不会用到 |

姿势歪一点没关系，但**不要带骨骼动画的初始变形**：导出前请把姿势应用到网格（Blender 里 `Ctrl+A → Visual Geometry to Mesh`，或直接导出不含骨架的静态网格）。

如果模型是绕 Y 轴转过的（比如面朝 -Z），不用回 Blender 改，在 `body-regions.json` 里写 `"rotateY": 180` 即可。

### 形变目标（morph targets / shape keys）

这些是**可选**的：没有形变目标时，身高靠整体缩放实现，体重和三围滑块只会改描述文字，不会改外形。

形变目标按名字识别，工具只认下面这些名字（多余的会被忽略）：

| 名字 | 含义 | 由什么驱动 |
| --- | --- | --- |
| `female` | 女性体征 | 性别（中性给 0.5） |
| `fatUp` / `fatDown` | 偏胖 / 偏瘦 | BMI 相对 21.5 的偏差，−10 BMI 到 `fatDown` 满，+20 BMI 到 `fatUp` 满（权重 2） |
| `bustUp` / `bustDown` | 胸围增 / 减 | 反解出来的：加载时量一次每个目标各值多少厘米，运行时按滑块上的绝对厘米数配权重 |
| `waistUp` / `waistDown` | 腰围增 / 减 | 同上 |
| `hipUp` / `hipDown` | 臀围增 / 减 | 同上 |
| `muscleUp` | 肌肉量 | 暂未使用，预留 |

加载时会在基础体型和「每个目标单独做满」的体型上各量一遍胸围 / 腰围 / 臀围（腰部横截面的切线多边形周长，等价于皮尺量法），得到一张「每个目标值多少厘米」的标定表；每次改参数时再按这张表反解三围目标的权重，迭代三轮抹平交叉影响（腰围目标顺带把胸围抬一点这种）。所以**模型量出来的三围就是滑块上的数**，而不是「相对常规值的偏差」——`autoGirth()` 只负责在自动模式下给滑块填数。

标定和反解在这个 13380 顶点的模型上分别是 60ms（只在加载时跑一次）和 0.7ms/次，换更大的模型时注意这两处开销。

一个形变目标都没有名字时，会按上表顺序按索引对应（`0 → female`，`1 → fatUp`，……），所以顺序对不上就务必写名字。

权重会**外插到 1 以上**（形变是线性位移，超过 1 就是继续往同方向推），上限 3：一个目标做满也就十几厘米，不外插的话胖到一半三围就顶死了。因此 `xxxUp` / `xxxDown` 请做成方向相反的两个独立目标，并且保证做满时形状仍然干净——3 倍时腋下、胯部会开始自穿插的目标，做出来的胖体型会破面。工具只做加权叠加，不会互斥处理。

反过来，三围滑块的两端未必都能到：这个模型的腰围大约能长到「身高 × 0.70」（172cm 上约 121cm，155cm 上约 106cm），再往上滑块数字还能加，模型不再变粗。想覆盖满量程就得让 `waistUp` 这类目标本身做得更狠。

## body-regions.json 的格式

没有这个文件时，工具会按几何自动分区：躯干、头、颈、双臂（上臂/肘/前臂/腕/手）、双腿（大腿/膝/小腿/踝/脚），一共 23 个区。够用，但分不出手指、脚趾、五官，腋下附近的手臂和躯干也可能划错一点。想要精确到「左手食指中段」这种程度，就得给分区表。

```json
{
  "version": 1,
  "rotateY": 0,
  "regions": [
    { "id": 0, "kind": "torso", "name": "躯干" },
    { "id": 1, "kind": "head",  "name": "头部", "center": [0, 0.93, 0.03], "chin": 0.868, "top": 1.0 },
    { "id": 2, "kind": "limb",  "name": "左上臂", "side": "左",
      "from": [0.11, 0.79, 0], "to": [0.16, 0.60, 0],
      "t0": "靠近肩部", "t1": "靠近肘部",
      "aVec": [0, 0, 1], "lVec": [1, 0, 0] }
  ],
  "triangles": 41522,
  "facesB64": "AAAAAQEBAgIC…"
}
```

### 顶层字段

| 字段 | 说明 |
| --- | --- |
| `version` | 固定 `1` |
| `rotateY` | 可选，加载时先绕 Y 轴转多少度（度数，不是弧度） |
| `regions` | 部位表，数组下标即区号；**第 0 个必须是兜底区**，查不到面时用它 |
| `triangles` | GLB 的三角面总数，用来校验分区表和模型是否配套 |
| `faces` | 每个三角面的区号，长度等于 `triangles` 的数组 |
| `facesB64` | `faces` 的紧凑写法：一个面一字节，base64 编码。两者给一个即可，`faces` 优先 |

`triangles` 和 GLB 实际面数不一致时，控制台会警告并退回自动分区——改过模型就要重新导出分区表。区号超过 255 的分区表只能用 `faces`。

### 坐标与长度

**所有长度都按身高归一化**（除以模型总高），这样换身高时工具直接乘一个系数就行。比如身高 172cm 的模型上，一个在 y=149cm 的点写 `0.866`。

向量字段（`aVec`、`lVec`）是方向，不归一化处理，直接写单位向量。

### 每个区的字段

| 字段 | 适用 | 说明 |
| --- | --- | --- |
| `kind` | 全部 | 部位类型，见下表；决定了描述文字怎么生成 |
| `name` | 全部 | 中文部位名，会直接出现在描述里 |
| `side` | 成对部位 | `"左"` 或 `"右"` |
| `center` | `blob` `digitJoint` `head` `palm` `foot` `breast` `eye` `ear` | 区中心点 |
| `from` `to` | `limb` `finger` `toe` `neck` | 肢体轴的两端，`from` 是近端（靠躯干），`to` 是远端 |
| `t0` `t1` | `limb` `finger` `toe` | 轴向两端的说法，如 `"靠近肩部"` / `"靠近肘部"`；中间自动说「中段」 |
| `aVec` | 多数 | 前后参考轴，指向「前面」那一侧 |
| `lVec` | 多数 | 侧向参考轴，指向 `axes.lPos` 那一侧 |
| `axes` | 多数 | 四个方位词 `{ aPos, aNeg, lPos, lNeg }`，默认 `前面/后面/外侧/内侧` |
| `noFacing` | `limb` 等 | 为 `true` 时只说轴向位置，不说朝向（细手指用得上） |
| `tip` | `finger` `toe` | 指（趾）尖坐标，描述里会附「距指尖约 x.x cm」 |
| `ext` | `eye` `ear` | 三个半轴长 `[x, y, z]`，用来把命中点归一化 |
| `zone` | `foot` | `"fore"` 前脚掌 / `"rear"` 后脚跟，分成两个区精度更高 |
| `zSpan` | `foot` | 该区前后方向的半跨度 |
| `chin` `top` `half` | `head` | 下巴高度、头顶高度、半高 |

`axes` 举例：肘部写 `{ "aPos": "肘窝(前面)", "aNeg": "肘尖(后面)", "lPos": "外侧", "lNeg": "内侧" }`，
描述就会变成「左肘 肘尖(后面)」而不是干巴巴的「左肘 后面」。

### kind 一览

| kind | 生成的说法 | 备注 |
| --- | --- | --- |
| `torso` | 按高度分 8 段 × 前/后/侧，如「上腹部(胃区)」「两肩胛之间(上背正中)」 | 不看 `name`，整个躯干只要一个区 |
| `head` | 额头、眉心、颧骨、后脑等，按 `chin`~`top` 的比例分 | 需要 `chin` `top` |
| `neck` | 颈前、后颈、侧颈 | 需要 `from` `to` |
| `limb` | `name` + 朝向 + 轴向位置 | 上臂、前臂、大腿、小腿 |
| `blob` | `name` + 朝向 | 肘、腕、膝、踝这类关节 |
| `palm` | 手心、手背、大鱼际、小鱼际、桡侧、尺侧 | `name` 建议写 `"左手"` |
| `foot` | 脚底、脚背、脚跟、足弓、内外侧 | 配合 `zone` `zSpan` |
| `finger` `toe` | 同 `limb`，另附「距指(趾)尖约 x.x cm」 | 需要 `tip` |
| `digitJoint` | 指节，`name` + 朝向 | |
| `breast` | 关闭私密部位时说「(内衣遮挡区)」，开启后细分乳晕、下缘等 | |
| `eye` `ear` | 上/下眼睑、内/外眼角；耳廓、耳垂、耳后 | 需要 `center` `ext` |
| `face` | 直接用 `name` | 鼻尖、鼻翼、嘴唇这类名字本身够准的小部件 |
| `sym` | `name` + 正中 / 左半侧 / 右半侧 | |

### 私密部位

分区表里不用管遮挡逻辑：躯干下腹、臀部、胸部（`breast` 区）的说法由页面上的「显示私密部位」开关控制，关着的时候只给「下腹/胯部(内衣遮挡区)」这类粗略说法。内衣带是运行时按躯干横截面现算的，不需要在模型里建。

## 从哪弄模型

推荐 **MakeHuman**（或 Blender 插件版 **MPFB2**）：

- 导出的人体网格是 CC0，商用私用都不受限（插件本体是 AGPL，不影响导出结果）；
- 自带性别、胖瘦、三围滑块，正好对应这里需要的形变目标；
- 可以直接导出 glTF，或者存成 `.mhx2` 到 Blender 里再导出。

其它可用来源：Blender 自带的 Human Base Meshes（CC0）、SMPL-X 系列的模板网格（注意 SMPL-X 只许非商用研究用途）。

拿到模型后用 `tools/blender-export-body.py` 在 Blender 里跑一遍，可以同时生成 `body.glb` 和按顶点组划分的 `body-regions.json`：

```
blender --background 你的模型.blend --python tools/blender-export-body.py -- --out assets/
```

细节见脚本开头的注释。
